测试数据的构造标准：
  1. 每个 batch row 的 seqlen 在 MIN_SEQLEN 和 MAX_SEQLEN 闭区间内可复现地无放回随机采样；各 row 的 seqlen 保持不同。MIN_SEQLEN == MAX_SEQLEN 时保留等长测试模式。
  2. 随机构造 query 和 key 和 weight ，因此理论上 top 2048 index 理论上应该是均匀分布在整个序列里面。
  3. 对于 seqlen <= CACHE_SIZE 的 row，miss_count 固定为 0；对于 seqlen > CACHE_SIZE 的 row，miss_count 在可行范围内从 MIN_MISS_COUNT 到 MAX_MISS_COUNT 随机取值。
  4. cache_slots 中应该有 min(seqlen, CACHE_SIZE) 个有效值，且有效值保持 unique、取值位于 [0, CACHE_SIZE)。当 seqlen >= CACHE_SIZE 时，有效值集合刚好是 0~CACHE_SIZE-1。
  5. 对每个 batch row 按该 row 的实际 seqlen 构造 cache_slots：
        5.1 seqlen <= CACHE_SIZE 时，缓存 [0, seqlen) 内的全部 token，不构造 miss。
        5.2 seqlen > CACHE_SIZE 时，从 top2048 中随机挑选 (2048-miss_count) 个 hit_index。
        5.3 从 top2048 之外随机挑选 CACHE_SIZE-(2048-miss_count) 个 other_index。
        5.4 把 hit_index 和 other_index 拼成 cached_index，并将唯一的有效 slot 随机分配给这些 token。


lightning_indexer_decode_update 和 lightning_indexer_decode_update_pool 的验收标准：对于每一个 batch 独立检验：
  1. 令 K=min(seqlen, 2048)，topk_index[:K] 与 lightning_indexer_decode[:K] 集合相同。
  2. topk_index[K:] 和 topk_slots[K:] 全部为 -1 padding。
  3. topk_slots[:K] 的值全部 >= 0 且 < CACHE_SIZE。
  4. 使用 topk_index[:K] 索引 new cache_slots 得到的值与 topk_slots[:K] 逐项相等。
  5. 使用 topk_index[:miss_count] 索引 old cache_slots 得到的值全部为 -1。
  6. hit 后缀在 old cache_slots 中的值与 topk_slots[miss_count:K] 逐项相等。
  7. new cache_slots 中有 min(seqlen, CACHE_SIZE) 个有效值，且有效值保持 unique；seqlen>=CACHE_SIZE 时值集合刚好是 0~CACHE_SIZE-1。
  8. miss_count 等于样例构造值，也等于 count(old_cache_slots[b, topk_index[:K]] == -1)。

request pool 额外验收：
  1. req_pool_entries 是 [B] 的唯一 int32 pool row 映射，默认 pool_size=B+7。
  2. pool 算子在 cache_slots[req_pool_entries[b]] 上得到与普通 update 相同的逐 batch 行语义。
  3. 未被 req_pool_entries 映射的 pool row 在算子调用后保持逐项不变。



不需要作为验收条件的：
  1. topk 分布均匀不要作为验收条件： 随机 query/key/weight 下，top2048 理论上大致会散在全序列，但这个只能作为数据构造直觉，不应该写成 hard check。真正验收还是和 LightningIndexerDecode 的输出做 multiset 对比。
  2. 每个 batch 独立检查： cache_slots 的 unique / count / range 建议都按 batch row 检查。每行独立检查。


一些参数约束：
- 0 <= MIN_MISS_COUNT <= MAX_MISS_COUNT <= 2048
- 0 <= MIN_SEQLEN <= MAX_SEQLEN < 262143
- 2048 < CACHE_SIZE < 16383
- 对于 seqlen > CACHE_SIZE 的 row，目标 miss_count 必须不超过 seqlen-CACHE_SIZE


一些概念澄清：
  1. old cache_slots 是指被算子更新之前的 cache_slots
  2. new cache_slots 是指被算子更新之后的 cache_slots
  3. 测试脚本可调参数：
      3.1 CACHE_SIZE 默认设为 8192
      3.2 MIN_MISS_COUNT 默认设为 0 ,  MAX_MISS_COUNT 默认设为 200
      3.3 MIN_SEQLEN 默认设为 32768，MAX_SEQLEN 默认设为 65536
  4. 不要叫 key_seq ，测试和文档里统一叫 seqlen （key的序列长度）


注意：
1. update 正确性由 test.py 验收，性能由 perf.py 测试。
2. 另外要注意，每次调用算子前要复制 cache_slots ，避免原地修改 cache_slots 导致影响后面的算子的命中率
3. test_*.py 只验收正确性，perf_*.py 只测试时延
